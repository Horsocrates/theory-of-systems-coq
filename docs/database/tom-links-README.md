# База связей «том ↔ формализация» — `tom-links.json`

Заведена 12.11.2026 в ходе аудита тома «Математика» (ТЗ: `Книги/Аудит-тома-Математика/00 ТЗ.md`).
Источник истины — `tom-links.json`; виды на Markdown генерируются скриптом и руками не правятся.

```
docs/database/
  tom-links.json            — база: одна запись = одна связь «место в томе ↔ теорема ↔ файл»
  tom-links-by-chapter.md   — вид по главам (сгенерирован)
  tom-links-by-file.md      — вид по файлам формализации (сгенерирован)
  tom-links-generate.cjs    — JSON → два вида:  node docs/database/tom-links-generate.cjs
  tom-links-README.md       — этот файл
```

`generate.ps1` (генератор базы по файлам) `tom-links.json` пропускает: это не шард кластера.

## Поля записи

| поле | что в нём |
|---|---|
| `batch` | из какой проверки запись: `sverka-2026-11-12` (сверка цены 12.11), `audit-part-NN` (аудит части) |
| `chapter`, `line` | путь главы от «Том Математика» и строка начала цитаты; при `"root": "library"` путь идёт от «Библиотека» (сводные страницы) |
| `claim` | цитата страницы дословно (пробелы и переводы строк не значимы) |
| `theorem`, `file`, `file_line`, `file_num` | имя, путь файла от корня репозитория, строка объявления, номер файла по `_files.tsv` (`null` — файл новее нумерации) |
| `kind` | вид объявления (`Theorem`, `Lemma`, `Definition`, …; `файл`, `модуль`, `внешнее` — имя стандартной библиотеки, конструктор или поле записи) |
| `statement` | утверждение из `.v` (до 700 знаков) |
| `assumptions` | вывод `Print Assumptions` дословно; `not-checked`, если не проверялось; «не применимо» для нотаций и тактик |
| `page_price` | что о цене говорит страница |
| `verdict` | `ok` · `mismatch-price` · `mismatch-statement` · `missing-name` · `wrong-number` · `not-checked` |
| `checked` | дата проверки |
| `note` | пояснение одной фразой |
| `lines` | все строки главы, где имя встречается в обратных кавычках |
| `file_sha` | SHA-1 файла `.v` на день проверки: файл изменился — запись стоит пересмотреть |
| `auto` | `true` — запись создана автоматически для простого упоминания имени или файла (проверено только существование) |

Вердикт записей пакета `sverka-2026-11-12` относится к цене (то, что сверялось 12.11); формулировки сверяются при
аудите своей части. Нечестный статус («доказано» вместо «наблюдение») записывается как `mismatch-statement` с
пометкой «статус: …».

## Как записи попадают в базу

Проверка главы оформляется ведомостью — `Книги/Аудит-тома-Математика/ведомости/*.json` (ручные записи: строка,
теорема, цитата, цена по главе, вердикт, пометка). Инструмент дополняет механические поля сам:

```
node Книги/Аудит-тома-Математика/tools/tom-links.cjs merge <ведомость.json>   # внести (заменяет записи того же batch и главы)
node Книги/Аудит-тома-Математика/tools/tom-links.cjs stats                    # счёт по вердиктам
node docs/database/tom-links-generate.cjs                                     # обновить виды
node Книги/Аудит-тома-Математика/tools/tom-status.cjs check                   # сторож: база против компилятора и страниц
```

`Print Assumptions` берётся из отдельной сборки вне OneDrive (`C:\Users\abary\tos-audit-build`,
`tools/tom-build.cjs sync` + `build`); `.v` и `_CoqProject` при этом не меняются.
