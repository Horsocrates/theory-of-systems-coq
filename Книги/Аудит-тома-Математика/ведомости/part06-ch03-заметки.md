```coq
Definition l1_close (a b : Q) (f g : SI.StepFun) (eps : Q) : Prop :=
  exists h : SI.StepFun,
    inside a b h /\
    (forall x, step_eval h x == step_eval f x - step_eval g x) /\
    SI.step_fun_norm h < eps.

(* близость в L1 влечёт близость интегралов -- без условий на разбиения *)
Theorem l1_close_integral : forall a b f g eps, a < b ->
  inside a b f -> inside a b g -> l1_close a b f g eps ->
  Qabs (SI.step_fun_integral f - SI.step_fun_integral g) < eps.

Record L1On (a b : Q) := mkL1On {
  on_seq : nat -> SI.StepFun;
  on_inside : forall n, inside a b (on_seq n);
  on_cauchy : forall eps : Q, eps > 0 -> exists N : nat, forall m n : nat,
    (N <= m)%nat -> (N <= n)%nat -> l1_close a b (on_seq m) (on_seq n) eps }.

Definition on_integral {a b : Q} (F : L1On a b) (n : nat) : Q :=
  SI.step_fun_integral (on_seq F n).

Theorem l1_on_integral_cauchy : forall a b (F : L1On a b), a < b ->
  forall eps : Q, eps > 0 -> exists N : nat, forall m n : nat,
    (N <= m)%nat -> (N <= n)%nat -> Qabs (on_integral F m - on_integral F n) < eps.

Corollary l1_on_integral_is_Cauchy : forall a b (F : L1On a b), a < b ->
  is_Cauchy (on_integral F).

(* прежнее определение -- частный случай: на общем разбиении почленная разность даёт L1-близость *)
Lemma aligned_close : forall a b f g eps,
  SI_aligned f g -> inside a b f ->
  SI.step_fun_norm (SI.step_fun_diff f g) < eps -> l1_close a b f g eps.
```

Доказательство `l1_close_integral`: список `f ++ step_fun_scale (-1) g` и список `h` задают одну функцию точки,
поэтому по `step_integral_depends_on_function` (расхождение 1) их интегралы равны; интеграл первого равен

ступенчатой функции — `step_to_l1_on`. Контрпример `wide` в новый тип не входит (нет общего отрезка), чередование

Обоснование на бумаге, что `l1_close` есть классическая $L^1$-близость: для всякой записи `h` функции $\varphi$
верно $\int|\varphi| \le \sum |v_i|\,w_i$, а запись с непересекающимися интервалами (поправки в отдельных точках —
ступенями нулевой ширины) даёт равенство. Компилятором это равенство не проверялось.

## Сомнительные места (расхождением не являются)

1. **Ступенчатая функция — произвольный список ступеней (стр. 60–63).** В типе `StepFun` нет условия, что
   интервалы не пересекаются или составляют разбиение (шапка `StepIntegral.v` говорит о разбиении; в записи его
   нет). Список есть формальная сумма индикаторов с весами; сумма $\sum v_i w_i$ остаётся её интегралом. Но
   `step_fun_norm` ($\sum |v_i|\,w_i$) равна интегралу модуля только при непересекающихся интервалах, в общем
   случае она его оценивает сверху. Страница о норме списка с пересечениями ничего не утверждает.
2. **Шесть копий типа.** Запись `Step` и определения `StepFun`, `step_integral`, `step_fun_integral` повторены в
   шести файлах `src/analysis` (в `L1Space.v` — с пометкой «Replicate StepIntegral definitions to avoid import
   issues»). Для компилятора это разные типы: леммы `StepIntegral.v` к ступенчатым функциям `L1Space.v` не
   применимы, и `L1Space.v` доказывает свои (`step_integral_app`, `integral_fun_scale`). Страница подаёт L¹ как
   пополнение тех же ступенчатых функций; связь держится на совпадении текста определений. Мост между копиями —
   `to_l1`, `to_l1_integral` (`Check2.v`, раздел 3).
3. **«Интеграл-процесс на ограниченных функциях», «сам интеграл — предел этих сумм» (стр. 35, 77–79).**
   `lebesgue_process` определён для всякой `f : Q -> Q`; для ограниченной доказана оценка каждой стадии
   (`lebesgue_bounded`), а не сходимость. В общем случае сходимости нет: для функции на $[0,1]$, равной 1 в
   точках с знаменателем — степенью двойки и 0 в остальных, сумма Римана при $n + 1 = 2^m$ равна 1, а при простом
   нечётном $n + 1 = p$ равна $1/p$ (проверено на бумаге). Страница сходимость доказанной не называет («естественно
   читать»). В `src` сходимость процесса доказана для производных (`ftc_integral_process_Cauchy`,
   `process/ProcessFTC.v:203`), для постоянных (`const_riemann_cauchy`) и — в пробном файле — для ступенчатых
   функций (`step_riemann_cauchy`).
4. **«Совпадение с Риманом» в перечне доказанного (стр. 196–197).** В процессном слое это равенство по
   определению; страница оговаривает это на стр. 80–83 и 165–166, в самом перечне оговорки нет.
5. **«На ограниченных функциях — по определению» (стр. 165–166).** Определение `lebesgue_process` ограниченности
   не требует; совпадение по определению верно для всякой функции.
6. **«Пополнение встроено в самый тип» (стр. 103–106).** Сказано честно, что теоремы Рисса–Фишера нет. Теорем о
   пределе последовательности L¹-процессов в `L1Space.v` нет вовсе; слова «представители пополнения строятся
   напрямую» означают лишь, что элемент типа есть последовательность.
7. **`l1_constant_integral` (сноска 5).** Лемма — об одной ступени на $[0,1]$, вложенной постоянной
   последовательностью; страница приводит имя без пересказа.
8. **Два файла `ProcessLebesgue.v`.** Сноска 3 называет каталог `src/process/`, и все три имени
   (`lebesgue_process`, `lebesgue_riemann_equiv`, определение через `riemann_process`) стоят именно там. Файл
   `src/stdlib/ProcessLebesgue.v` — другой по содержанию (перестановка конечных сумм 2×2 и 3×3); страница на него
   не ссылается, имена приписаны верно. `riemann_process` объявлен в `process/ProcessSimple.v`, `process_equiv` — в
   `process/ProcessCore.v`; сноска файлов для них не называет.
9. **«Все они доказаны как точные тождества» (стр. 65–66).** Монотонность — неравенство; аддитивность и
   однородность — равенства по `Qeq`.

## Вне главы (замечено в исходниках, страницы не касается)

1. **`L1Space.v`.** Шапка: «25 Qed» при 16; «Rules: Cauchy property, linearity, monotonicity» — леммы о
   монотонности в файле нет, линейность представлена `integral_fun_scale` и `step_integral_app`. Раздел
   «INTEGRAL SEQUENCE IS CAUCHY» содержит одну лемму о двух ступенях. `l1_equiv_integral` (`:178`) повторяет
   определение `l1_equiv`; комментарий «l1_equiv implies integral convergence» утверждению не соответствует.
   Определена, но не использована `step_fun_add` (`:64`).
2. **`StepIntegral.v`.** Шапка: роль «pointwise evaluation» — определения значения в точке нет; «Rules: Linearity»
   — есть аддитивность по конкатенации и однородность одной ступени; комментарий «where {[aᵢ,bᵢ]} partition
   [a,b]» — условия разбиения в типе нет. `Qabs_nonneg_local` (`:174`) — переименование `Qabs_nonneg`.
3. **`process/ProcessLebesgue.v`.** Шапка: «15 Qed» при 17; «Rules: step below f -> integral below integral of f,
   monotone convergence» — таких утверждений в файле нет. Раздел «Triangle Inequality»: `lebesgue_abs_bound`
   (`:194`) дословно совпадает с `lebesgue_bounded` (`:51`) — это оценка $|\int f| \le M\,(b-a)$, а не
   $|\int f| \le \int |f|$. `lebesgue_is_process` (`:251`): заключение `exists proc, forall n, Qabs (proc n) <= M *
   (b - a)` не упоминает `f`; свидетелем годится постоянный нулевой процесс. `lebesgue_convergence_rate := 1 # 2`
   (`:244`) с процессом не связано (такие определения в Части V сняты словом автора). Комментарии «For bounded f»
   стоят над леммами без посылки ограниченности (`:131`, `:142`). `lebesgue_indicator_is_measure` (`:158`) и
   `lebesgue_integral_equiv` (`:143`) — равенства по определению.
4. **`process/ProcessMeasureTheory.v`.** Шапка: «17 Qed» при 22. `measure_convergence_rate := 1 # 2` (`:271`) —
   то же, что в пункте 3. `measure_is_process` (`:278`): посылка `c <= d` не используется, заключение не упоминает
   `c`, `d`. `measurable_measure` (`:150`) принимает только два значения: `b - a` или 0.
5. **`stdlib/ProcessLebesgue.v`.** Первая строка: «Convergence theorems for process integrals»; в файле —
   перестановка слагаемых в суммах 2×2 и 3×3, лемма `monotone_sum` (сложение двух неравенств) и конъюнкция
   `lebesgue_foundation`; комментарий «Dominated convergence … AUTOMATIC» теоремой не сопровождается.
