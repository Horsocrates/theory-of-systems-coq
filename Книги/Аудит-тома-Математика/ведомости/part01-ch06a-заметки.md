```coq
  match l with
  | L1 => A
  | LS l' => Carrier A l' -> Prop
  end.

Definition member {A : Type} {l : Level}
  (x : Carrier A l) (S : Carrier A (LS l)) : Prop := S x.

Definition nonempty_collections (A : Type) (l : Level) : Carrier A (LS (LS l)) :=
  fun S => exists x : Carrier A l, member x S.

Definition all_of_level (A : Type) (l : Level) : Carrier A (LS l) := fun _ => True.

Lemma carrier_step : forall (A : Type) (l : Level),
  Carrier A (LS l) = (Carrier A l -> Prop).
Proof. reflexivity. Qed.
```

Здесь совокупность уровня `LS l` состоит из объектов уровня `l` и только из них; вложение на уровень ниже
записывается (`nonempty_collections`), совокупность всех объектов уровня лежит уровнем выше (`all_of_level`), а
самопринадлежность не записывается — `member S S` отвергается проверкой типов (`Fail5.v`: «The term "S" has type
"Carrier A (LS l)" while it is expected to have type "Carrier A (LS (LS l))"»). В таком носителе запрет $P1$
обеспечен типами и согласован с порядком `<<` на метках.

**(б) Поправить слова:**

> **Стратификация уровней.** Принцип $P1$ (Глава 4) задаёт иерархию уровней: $L1$, `LS L1`, `LS (LS L1)` и так далее.
> Объекты различены по уровням; объект уровня $L$ не может содержать объекты того же уровня. В формализации уровни
> заданы собственным индуктивным типом меток `Level`, и у порядка на метках нет петель (`P1_no_self_membership`).
> Система типов CIC несёт запрет того же рода в своей универсной иерархии ($Prop$, $\texttt{Type}_0$,
> $\texttt{Type}_1$, $…$): тип не содержит тип своего универса. Содержательно оба выражают структурное следствие акта
> различения — невозможность самовключения, разобранную в Главе 4.

То же относится к сноске 14 второй половины главы («формальная иерархия ToS строится поверх универсной иерархии CIC»).

## Расхождение 10. Модули стандартной библиотеки «привносят то, чего в ToS нет» (стр. 1045–1058)

**Было:**

> - `Coq.Logic.ClassicalDescription` — определение объекта через свойство, с опорой на Аксиому Выбора.
> - `Coq.Logic.ClassicalEpsilon` — гильбертовский $\epsilon$-оператор, выбирающий произвольного свидетеля, с опорой на
>   Аксиому Выбора.
> - `Coq.Logic.IndefiniteDescription` — неопределённое описание, ещё одна форма выбора.
>
> В ToS-репозитории эти модули не импортируются. Это не есть запрет в смысле волевого акта — это естественное
> следствие того, что данные модули привносят в CIC то, чего в ToS нет (Аксиома Выбора и её варианты). Если бы они
> были импортированы, в репозитории появилась бы конструкция, не имеющая основания в выводе из акта различения.

**Проверка.** Аксиомы трёх модулей (исходники стандартной библиотеки Rocq 9.0, `Stdlib/Logic/`):

| модуль | что подключает и объявляет | утверждение аксиомы |
|---|---|---|
| `IndefiniteDescription` | `Axiom constructive_indefinite_description` (`:21`) | `forall (A : Type) (P : A->Prop), (exists x, P x) -> { x : A \| P x }` |
| `ClassicalEpsilon` | `Require Export Classical` (`:20`); `Axiom constructive_indefinite_description` (`:25`) | `classic` и то же, что строкой выше |
| `ClassicalDescription` | `Require Export Classical` (`:21`), `Require Export Description` (`:22`); в `Description.v:19` — `Axiom constructive_definite_description` | `classic` и `forall (A : Type) (P : A->Prop), (exists! x, P x) -> { x : A \| P x }` |

Аксиома неопределённого описания совпадает с `L4_witness` (`ToS_Axioms.v:105`) дословно; аксиома определённого

**В чём расхождение.** Аксиомы названных модулей по утверждению совпадают с аксиомами ToS или следуют из них; модули

**(а) Довести формализацию.** До слов главы — только ослаблением принятой аксиомы: если аксиомой объявить
утверждение `L4_definite` (свидетель единствен), модули `IndefiniteDescription` и `ClassicalEpsilon` действительно
будут привносить большее, а слова «свидетель не выбирается, он определён» получат формальную опору. Часть нужного
для этого сделана: информативное исключённое третье получается уже из определённого описания (`Check.v`, Closed under
the global context — посылки взяты переменными раздела):

```coq
Section FromDefiniteDescription.
  Hypothesis em : forall P : Prop, P \/ ~ P.
  Hypothesis definite : forall (A : Type) (P : A -> Prop), (exists! x, P x) -> { x : A | P x }.

  Theorem informative_em_from_definite : forall P : Prop, {P} + {~ P}.
  Proof.
    intro P.
    assert (Hex : exists! b : bool, if b then P else ~ P).
    { destruct (em P) as [HP | HnP].
      - exists true. split; [exact HP |].
        intros [|] Hb; [reflexivity | exfalso; exact (Hb HP)].
      - exists false. split; [exact HnP |].
        intros [|] Hb; [exfalso; exact (HnP Hb) | reflexivity]. }
    destruct (definite bool (fun b : bool => if b then P else ~ P) Hex) as [b Hb].
    destruct b; [left | right]; exact Hb.
  Qed.
End FromDefiniteDescription.
```

и в репозитории есть теоремы с окончанием `_definite`, принимающие определённое описание посылкой
(`Schroeder_Bernstein_definite` и другие). Какие из 86 теорем, стоящих на `L4_witness`, обходятся единственным
свидетелем, не проверялось; по шапке `ChoicePriceMap.v` (`:35–42`) неединственный свидетель нужен в строках
`RSurjectionBridge`, `RIntervalAnyCauchy`, `RContinuumHypothesis`, `RZermeloDeterminacy`. Это решение об аксиоматике —
за автором; без него расходятся слова, и править следует их.

**(б) Поправить слова:**

> В стандартной библиотеке Rocq есть модули, объявляющие принципы описания собственными аксиомами:
>
> - `Coq.Logic.ClassicalDescription` — исключённое третье вместе с определённым описанием: извлечением единственного
>   свидетеля.
> - `Coq.Logic.ClassicalEpsilon` — исключённое третье вместе с неопределённым описанием и построенный на них
>   гильбертовский $\epsilon$-оператор.
> - `Coq.Logic.IndefiniteDescription` — неопределённое описание.
>
> В ToS-репозитории эти модули не импортируются. Причина не в том, что они сильнее принятого: по утверждению их
> аксиомы совпадают с `classic` и `L4_witness` (определённое описание — с их следствием `L4_definite`), и всё, что
> эти модули дают, из двух объявлений ToS выводится. Причина в учёте: импорт добавил бы второе объявление того же
> утверждения под другим именем, и вывод `Print Assumptions` перестал бы показывать, что теорема стоит именно на
> `L4_witness`. В комментарии файла `ToS_Axioms.v` соответствующие модули явно отмечены как не подлежащие импорту —
> эта отметка есть правило учёта, не дополнительный постулат.

Вводную фразу раздела (стр. 1047–1048: «модулей, реализующих классические конструкции, оказавшиеся невозможными в
ToS») при этой правке следует снять: конструкции этих модулей в ToS выводимы.

Правка меняет названную в главе причину запрета, а не только сведения о модулях; содержательное различение автора
(`L4_witness` — определённость существования, а не выбор) остаётся на стр. 501–615 и этой правкой не затрагивается.
Формально оно выражается не различием утверждений (утверждение то же, что у стандартной аксиомы), а различием
употреблений — единственный свидетель или один из многих (см. «Сомнительные места», стр. 542–545).
