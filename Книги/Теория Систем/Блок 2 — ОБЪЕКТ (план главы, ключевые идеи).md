# Блок 2 — ОБЪЕКТ: каноническая система (план главы, ключевые идеи)

## Роль и форма блока
- **Роль:** каноническая E/R/R-система (`FunctionalSystem`) и **теорема представления**.
- **Тезис:** **система = триада ⊕ L4-гейт ⊕ P1-градация**; триада ОДНА систему НЕ определяет (это результат, не дефект).
- **E/R/R-линза:** Rules = Constitution **гейтит**, Roles = relations, Elements = domain; **`fs_functional`** (Rules применены к (E,R) и ВЫПОЛНЕНЫ) = точка их ВЗАИМОДЕЙСТВИЯ — семя ранговой асимметрии (2.4) и закона композиции (Блок 3).
- **Вход из Блока 1:** цепь дала ОБЪЕКТ; здесь разбираем его изнутри. **Выход в Блок 3:** объекты складываются.

## Спина: 2.1 → 2.8

### 2.1 `FunctionalSystem` — триада в одной записи ✓
- Одна запись несёт все три аспекта. **`fs_functional`** (Rules применены к (E,R) и выполнены) = семя ранговой асимметрии и закона композиции.
- `Constitution := ∀ D R, Prop` (правило = условие на ⟨носитель, отношение⟩); примеры **Trivial / Equivalence**; шесть полей записи.
- ✓

### 2.2 Экстракция `get_*` — разбор, не сборка ✓
- Триада **вытягивается** из готовой системы: `get_Elements / get_Roles / get_Rules`. Эпистемически мы РАЗБИРАЕМ систему, а не собираем её из трёх частей.
- Категориальная маркировка: три аспекта взаимно-исключающи (`categories_exclusive`, `err_element_not_rule`) — Element ≠ Role ≠ Rule.
- ✓

### 2.3 Теорема представления ✓★ *(флагман блока)*
- **Система = триада ⊕ L4-гейт ⊕ P1-градация.** Что достаёт триаду до полной системы: functional-факт (`fs_functional`, L4-гейт) + level-валидность (P1-градация).
- **`triple_not_complete`** (ядро, честно): триада ОДНА недоопределяет — две системы делят всю триаду (Elements/Roles/Rules), но различаются P1-градацией ⇒ триада **необходима, не достаточна**.
- Поправка к наивному «система = тройка»: то было бы переописанием; честная теорема показывает, **чего тройке не хватает**.
- ⚠ Без уникальности-с-точностью-до-доказательств (`fs_functional`/`level_valid` : Prop — нужна proof irrelevance, аксиома); работаем на уровне ДАННЫХ.
- ✓★

### 2.4 Ранговая асимметрия Rules > Roles > Elements ✓
- Проза свода / `ERR_FRAMEWORK` стала **теоремой**: **Rules — гейт**; пара (Elements, Roles) **недоопределяет** Rules (две системы, одинаковые E и R, разные Rules).
- Здесь — доказательство **генеративного порядка** Rules→Roles→Elements (правило первично, элементы производны).
- ⚠ Честно: не переформулировка `fs_functional`, а структурная асимметрия (в типах записи) с доказанными следствиями.
- ✓

### 2.5 Неприводимость триады ✓
- **Три независимых DOF:** ни один аспект не сводится к двум другим (Rules независимы — 2.4; Roles независимы от Elements; Elements независимы — иной ТИП носителя).
- Формализует «три аспекта, ни один не опускаем» как независимость.
- ✓

### 2.6 Три уровня бытия + Status ✓
- **Лестница пресуппозиции:** Existence (**A = 1**, снова M1) → Belonging (A ∈ T) → Functioning (A играет роль R). Каждый уровень презюмирует предыдущий; строгая вложенность.
- **Status (чем СТАЛ после правил) ≠ Role (ПОЧЕМУ здесь).** Status **выведен** (status e := применённое правило), не новый примитив.
- Заменяет документационный маркер `three_levels_of_being := True` реальной структурой.
- ✓

### 2.7 Актуализация `fs_lift` ✓
- **Products(L) = Elements(L+1) как ОПЕРАЦИЯ** (не только инстанс Nat/Real/Enum): продукты уровня L становятся элементами уровня L+1.
- Превью вертикали (Блок 6) и моста к P4-процессу (Блок 7).
- ✓

### 2.8 Мост двух «System» ✓⚠
- Индексная критериальная **`System L`** (легаси; критерий, блокировка парадоксов P1/P2) → **`FunctionalSystem L`**: каноничен FunctionalSystem (Elements = члены, Roles = дискретное равенство, Rules = эквивалентность; P2-свидетель уровня → P1-градация).
- ⚠ Честно: это **ВЛОЖЕНИЕ, не изоморфизм** — критериальная System тоньше (нет родных Roles/Rules), E/R/R-образ богаче.
- ✓⚠

### (доп.) Хорошая форма системы ✓ *(волна I)*
- **Разрешимый предикат:** система хорошо сформирована ⟺ каждый компонент в **ровно одной** категории E/R/R **∧ нет само-референции** (P1 из 1.4).
- ℕ и шахматы проходят; **Рассел / Лжец / Греллинг — НЕТ** (парадоксы = ill-formed, не «растворены»).
- Связь: хорошая форма = условие применимости теоремы представления; парадокс = нарушение P1.
- ✓

→ *Объект разобран изнутри — Блок 3 показывает, как объекты СКЛАДЫВАЮТСЯ (морфизм / произведение / фактор / категория).*

## Честность (правила голоса для этой главы)
- Теорема представления — **честная**: триада необходима, не достаточна; «система = тройка» поправлено. ⚠ уникальность только на уровне данных (без proof irrelevance).
- Ранговая асимметрия — **структурная** (в типах), не переформулировка `fs_functional`.
- Мост System→FunctionalSystem — **вложение, не изо** (⚠).
- Парадоксы — **невозможны при хорошей форме**, не «растворяются».
- M1 держится: Existence = A=1 (2.6); вести от того, ЧТО ЕСТЬ.
