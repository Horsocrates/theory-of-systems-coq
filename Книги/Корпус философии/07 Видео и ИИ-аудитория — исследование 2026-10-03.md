# Видео к страницам и ИИ как аудитория — исследование 2026-10-03

Вопрос автора: записать видео на каждую тему — автор читает текст по-русски, сверху ИИ-дубляж на
другие языки, видеоряд создаёт Claude; затем YouTube и вставка на сайт. Второй вопрос: целевая
аудитория — ИИ.

Сведения о сервисах сняты веб-поиском 3 октября 2026 двумя исследовательскими агентами; цены и
условия перед оплатой сверить по первоисточникам. Неподтверждённое помечено.

## 3. YouTube

- **Автодубляж:** с февраля 2026 открыт всем авторам и включён по умолчанию; русский оригинал
  дублируется только на английский; править нельзя; отключается в Studio (Settings → Channel →
  Advanced settings → Allow automatic dubbing). https://support.google.com/youtube/answer/15569972
- **Свои аудиодорожки:** каналам с Advanced features; загрузка в Studio (Languages → Add language →
  Dub); длина дорожки должна совпадать с видео; через API не загружаются.
  https://support.google.com/youtube/answer/13338784
- **Загрузка по API:** `videos.insert` с июня 2026 — 1 единица, 100 загрузок в день; видео из
  непроверенного API-проекта остаются private до аудита; субтитры — `captions.insert`, 400 единиц.
  https://developers.google.com/youtube/v3/determine_quota_cost
- **Вставка:** `youtube-nocookie.com`; плееру нужен заголовок Referer.
  https://support.google.com/youtube/answer/171780

## 5. ИИ как читатель сайта

- **llms.txt** остаётся предложением; исследование Ahrefs (137 тыс. доменов, май 2026): 97 % файлов
  не получили ни одного запроса. Дёшево, но польза не показана. https://ahrefs.com/blog/llmstxt-study/
- **Боты.** Обучение: GPTBot, ClaudeBot, Google-Extended, CCBot. Поиск: OAI-SearchBot,
  Claude-SearchBot, PerplexityBot. Действия пользователя: ChatGPT-User, Claude-User, Perplexity-User.
- **Cloudflare.** С 15 сентября 2026 настройки ИИ-ботов разделены на Search, Training, Agent;
  включённый managed robots.txt запрещает GPTBot, ClaudeBot, Google-Extended. Разрешить: Security →
  Settings → AI bot policies = Allow; проверить AI Crawl Control, правила WAF, Bot Fight Mode.
  https://developers.cloudflare.com/ai-crawl-control/
- **Markdown для агентов:** по заголовку `Accept: text/markdown` — у Cloudflare функция Markdown for
  Agents на планах Pro и выше. JSON-LD прироста цитирований не показал.
- У сайта на 2026-09-25 не было `robots.txt` (файл 03).

## 6. Выводы Claude

1. **Основа видеоряда — программная**, в оформлении сайта: текст, определения, этимологии, таблицы,
   схемы вывода, в такт чтению. Экранный текст хранится в данных, поэтому английская версия
   перерисовывается из английской страницы.
2. **Иллюстрации** — открытые музейные коллекции для исторических фигур; ИИ-картинки — для
   абстракций, в едином стиле. **ИИ-клипы** — только заставка и переходы.
3. **Дубляж** — не автоперевод речи, а наш выверенный английский текст, озвученный клоном голоса
   автора или дикторским голосом; под него рендерится отдельное английское видео. Автодубляж YouTube
   на канале отключить: он не знает глоссария.
4. **Загрузка на YouTube** — руками автора через Studio; Claude готовит файл, заголовок, описание,
   главы по разделам, точные субтитры из текста страницы, обложку.
5. **ИИ как аудитория** — до модели доходит текст и структура в момент работы, а не видео. Значит:
   английская версия, единый канон без противоречий, открытый доступ ботам, машинно-читаемый слой
   (чистый Markdown, глоссарий и канон данными) и главное — Архитектура Рассуждения как инструмент,
   который агент может вызвать, с измерением пользы.

## 7. Архитектура Рассуждения как инструмент для ИИ — видение (ответ автору 2026-10-03)

### Что уже есть в репозитории

- `Architecture_of_Reasoning/` (январь 2026): машинно проверенная таксономия и **типизированная
  схема диагноза** `VerificationResult` — верно · нет конституции · нарушение домена (домен +
  механизм) · нарушение последовательности (два домена) · синдром · смешение уровней · домен
  пропущен. 124 теоремы, 0 Admitted.
- Детектор `AI_FallacyDetector.v` + извлечение в OCaml + `demo.py`. Решающая логика доказана, но
  **признаки текста извлекаются списками английских слов** («however», «idiot», «tradition»).
- `LLM_EXPERIMENT_RESULTS.md`: шесть примеров, часть ответов смоделирована, «6/6». Это проверка
  схемы, а не измерение качества; README сам называет слабым звеном извлечение признаков.
- Мастер-таблицы каталога (`quartz/tables/*.tsv`): по каждой ошибке — формулировка, механизм,
  пример, диагностический вопрос, связанные ошибки, домен; у контекстных методов — «когда валидно /
  когда ошибка». Колонка «Источник (Texas)» — происхождение номенклатуры.
- Январский слой расходится с нынешним каноном: 156 ошибок против 152 в каталоге, «dissolution»,
  порядок E/R/R.

### Предложение

**Разделение труда.** Читает текст сама модель: это её сильная сторона. Архитектура даёт ей форму.
Проверенное ядро проверяет, что диагноз составлен правильно.

**Инструмент — четыре процедуры.**

1. *Проход по доменам* — до ответа: шесть вопросов по порядку; модель записывает, что распознано,
   что прояснено, какая рамка выбрана, что с чем сравнено, что следует, где пределы.
2. *Диагноз рассуждения* — после черновика или для чужого текста: место сбоя (домен), механизм из
   каталога, диагностический вопрос, починка. Ответ — в доказанной схеме диагноза.
3. *Статус утверждения* — для ключевых утверждений: что дано, что выведено, что допущено; критерий
   честности из «Правды и истины»: заявленное совпадает с держимым.
4. *Проверка конструкции* — уровни и порядок определения: для само-применимых построений.

**Три обёртки одного содержания.** Навык (skill) для Claude; MCP-сервер для любых агентов
(`domain_pass`, `diagnose`, `catalog_lookup`); компактное «ядро» для системных подсказок. Источник
данных один — канон доменов и таблицы каталога, выгруженные в JSON: сайт, навык и сервер не
расходятся.

**Измерение.** Одна и та же модель в трёх условиях: без инструмента · с нейтральной инструкцией
той же длины · с инструментом. Наборы задач:

1. распознавание ошибок на открытых наборах (LOGIC, MAFALDA) — точность и тип;
2. ловушки рассуждения: базовая частота, варианты Монти Холла, Симпсон, ложные пресуппозиции —
   доля ошибок;
3. самопроверка: ответ на вопросы с известным ответом, затем аудит инструментом — сколько ошибок
   исправлено и сколько внесено;
4. позднее — разметка провалов агентов по доменам.

Метрики: точность, калибровка, цена в токенах. Публикуется всё, включая нулевой результат.

**Публикация.** Страница «Для ИИ и разработчиков»; открытый репозиторий с данными, навыком,
сервером и стендом измерения; короткая статья с результатами.

### Условия и риски

- Сначала — канон доменов (сейчас ведущие вопросы существуют в пяти версиях): инструмент строится
  с замороженных страниц АР.
- Рабочий язык инструмента — английский.
- Эффект на сильных моделях может оказаться малым; контрольное условие нужно именно для этого.
- Источник номенклатуры ошибок указать до публикации.
- Январский слой привести к канону или пометить как исторический.

### Порядок

1. Вычитка АР → замороженный канон доменов. 2. Выгрузка таблиц в JSON и навык v0. 3. Пилотное
измерение (нужен ключ API модели и небольшой бюджет). 4. MCP-сервер, страница, репозиторий, статья.
